# 传输与桌面交互验收（2026-11-08）

> 本文记录 11 月 8 日的历史实现。11 月 14 日已升级至 v2.4.1，并按用户要求完全移除旧内核补偿与清理日志兼容代码；删除和续传重新验证通过。当前状态见 [验证记录](validation.md)。

范围：用户确认的三项工作——删除清理、重启恢复、传输页/托盘/悬浮窗交互。环境为本机 Windows 10 x64，官方 BaiduPCS-Rust v2.4.0 后端，界面目标为参考最新版百度网盘，以下为当时已完成的验收记录。

## 1. 删除与清理

真实账号测试使用独立后端配置和本地目录；下载来源为已有的 `/客户端验证-*` 测试目录。没有删除用户网盘文件。

| 场景                                        | 结果                                                           |
| ------------------------------------------- | -------------------------------------------------------------- |
| 已有进度后删除单文件（本次 1,607,705 字节） | 任务消失，临时文件清理                                         |
| 暂停后删除（本次 883,869 字节）             | 通过                                                           |
| 批量删除运行中及排队任务                    | 通过                                                           |
| 删除后立即下载到相同路径                    | 新任务暂停后文件内容保持不变，旧清理不误删                     |
| 文件夹下载已有进度后删除                    | 按子任务准确路径清理，保留已完成文件与无关 `.downloading` 文件 |
| 清空完成记录                                | 下载文件保留，上传源文件和网盘文件保留                         |
| 删除后重启                                  | 已删除记录不恢复，已知临时路径无残留                           |

真实测试：`scripts/verify-transfer-lifecycle.cjs`；结果：`artifacts/transfer-lifecycle.json`。

新增三组回归最初全部失败：文件夹子任务残留、立即清理误删替代任务、清理计划无法跨客户端重启。修复后通过，另补充持久化任务保护、创建/清理串行和查询失败保护。`npm test` 共 12 项通过。

实现：`electron/cancelled-downloads.cjs` 保存准确路径的清理记录。删除前保存，删除后检查当前任务占用，按 2/5/10/20/30/60 秒重试；新建下载与清理共用串行队列。文件夹先暂停扫描，再取得子任务路径。正常退出时等待后端进程结束再完成清理；异常退出留下的记录在下次启动处理。只删除已记录路径的临时文件，不按目录/后缀递归清空。

这仍是客户端对上游 #192 的补偿，不是 Rust 分片退出竞态的根治。客户端异常退出后，未执行的清理依赖下次启动；未覆盖整个请求生命周期的上游取消行为仍由上游修复。

## 2. 重启恢复

独立后端的暂停/恢复测试通过；增加实际 Electron 主进程的四次启动/退出测试，使用正式的启动设置、IPC 分发、退出暂停和后台终止路径。

1. 上传随机 16 MiB 文件，在已传 4,194,304 字节时退出客户端，保存“自动继续关闭、悬浮窗关闭”。
2. 新进程读取原配置，上传恢复为暂停；手动继续并完成。创建下载，已有 277,838 字节进度时启用“自动继续、悬浮窗”，退出。
3. 新进程自动继续下载，SHA-256 与上传源文件一致；已完成上传记录仍存在。清空上传和下载记录后，源文件与下载文件内容不变。
4. 再次启动确认记录不复活，设置保留，悬浮窗仍停留在自己的 `#/float` 页面。

命令：`node scripts/verify-desktop-restart.mjs`。结果：`artifacts/desktop-restart-verification.json`。

另一次独立的运行中退出测试：上传 4,194,304 字节、下载 559,914 字节后退出并恢复成功；自动继续策略与最终哈希检查通过。结果：`artifacts/recovery-active-exit.json`。

真实上传只生成测试文件，保留供复核。隔离配置中的账号凭据副本及原始后端日志在测试结束时移除，报告不包含 Cookie 或签名下载地址。

## 3. 官方交互对照与桌面检查

依据本机官方窗口截图与用户此前提供的上传完成/悬停/下载进行中截图。没有把包内未启用的样式当作运行画面。

- 上传和下载工具栏：全部暂停 → 全部开始 → 全部删除；完成页清空全部。按钮含图标，禁用文字保持较深颜色。
- 下载完成页按实际画面改为文件名、大小、完成时间三列；上传完成页仍为四列，保留进度。当天显示时间，往日显示日期；大小与速度采用两位小数。
- 悬停和键盘聚焦时显示行内操作，操作组在文件名列右侧；完成项仅查看所在位置、清除记录。下载位置使用该任务自身路径。
- 活跃、暂停、失败、完成、秒传完成状态及批量操作分类隔离通过桌面测试；进行中显示速度、进度条、剩余时间，无 SVIP 文案。
- 搜索框在传输页保留；搜索文字与目录前进/后退历史跨页保留，传输页提交搜索可回到文件结果页。
- 关闭主窗口隐藏到托盘，后端仍运行；托盘双击和菜单可恢复/切换主窗口。
- 悬浮窗点击打开主窗口传输页，自己不跳页；速度只统计正在上传/下载的任务，忽略暂停/失败的旧速度。
- 悬浮窗移动后保存位置，关闭/重新打开恢复位置；托盘勾选状态与悬浮窗开关同步；无横向/纵向溢出。

命令：`npm run build`、`npm run test:desktop`。结果：`artifacts/smoke-result.json`。

截图使用明确标注的模拟数据：`desktop-transfer-hover.png`、`desktop-transfer-download-completed.png`、`desktop-transfer-upload-completed-hover.png`、`desktop-transfer-upload-active.png`、`desktop-float-transferring.png`。截图前等待渲染帧，避免 DOM 已更新但截图仍是上一页。

本轮完成的是上述传输与桌面交互范围，不代表整个官方客户端所有页面已像素级还原。未扩展分享、播放、同步备份等首版外功能；多显示器/DPI、长期断网、文件夹上传扫描中断仍属于后续专项测试。
